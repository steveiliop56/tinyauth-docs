title: Other OAuth Providers
description: Use any OAuth provider that is not already listed in the documentation.
---

This guide will show you how to set up Tinyauth with any OAuth provider that is OpenID Connect compliant. This allows you to use providers that are not already listed in the documentation.

## Requirements

A working OAuth provider that is OpenID Connect compliant and a good understanding of how to use your provider.

This guide will not go into specifics since each OAuth provider is different.

:::note
  Your OAuth provider will need to have emails linked to each account.
:::

## Key info

You need to know the URLs in which Tinyauth and your OAuth provider are accessible.
This guide is using placeholders for this info.
`<tinyauth_url>` for Tinyauth and `<provider_url>` for the OAuth provider.
Make sure to replace these placeholders with the actual URLs in the configuration steps below.

You will also need to know your providers endpoints for `authorization_endpoint`, `token_endpoint`, and `userinfo_endpoint`.
If your provider has a `.well-known/openid-configuration` URL then it can be used to discover the information.
Otherwise please refer to your provider's documentation to find the endpoints.
These endpoints are also using placeholders in this guide.

You also need the client ID and client secret. These use the `<client_id>` and `<client_secret>` placeholders respectively.

You will need to pick a descriptive name for your OAuth provider. This will be needed in three formats. **UPPERCASE**, **lowercase**, and **non-formated**.

- The uppercase format will be used for the environment variable keys.
- The lowercase format will be used for the callback/redirect URL
- The unformatted descriptive name will be shown to users (it can only have alphanumeric characters).

This descriptive name has the placeholders `<PROVIDERNAME>`, `<providername>`, and `<non-formatted provider name>`.

If you wanted your provider to be "My Provider" then `<PROVIDERNAME>` would be `MYPROVIDER`, `<providername>` would be `myprovider`, and `<non-formatted provider name>` would be `My Provider`.

## Configuring the OAuth provider

Create a new client in your OAuth provider. This client will need a callback/redirect URL of `https://<tinyauth_url>/api/oauth/callback/<providername>`.
You will need the client ID and client secret from your provider.

## Configuring Tinyauth

Add the following entries to your tinyauth service's environment section substituting placeholders:

```yaml
services:
  tinyauth:
    environment:
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_CLIENTID=<client_id>
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_CLIENTSECRET=<client_secret>
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_AUTHURL=<authorization_endpoint>
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_TOKENURL=<token_endpoint>
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_USERINFOURL=<userinfo_endpoint>
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_SCOPES=openid,email,profile
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_REDIRECTURL=https://<tinyauth_url>/api/oauth/callback/<providername>
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_NAME=<non-formatted provider name>
      - TINYAUTH_OAUTH_PROVIDERS_<PROVIDERNAME>_INSECURE=false # Change to true if your provider is using self signed certificates
```

:::caution
  OAuth alone does not guarantee security. By default, any OAuth account can
  log in as a normal user. To restrict access, use the `TINYAUTH_OAUTH_WHITELIST`
  environment variable to allow specific email addresses. Refer to the
  [configuration](/docs/reference/configuration) page for details.
:::

:::note
  With OAuth enabled, the `TINYAUTH_AUTH_USERS` or `TINYAUTH_AUTH_USERSFILE` environment variable can be
  removed to allow login exclusively through the OAuth provider.
:::

:::note
  Tinyauth supports using more than one OAuth proivder as long as the each have unique descriptive names.
  To set this up just follow this guide again for each OAuth provider while keeping the existing OAuth provider's environment variables intact.
:::

Restart Tinyauth to apply the changes. The login screen will now include an option to log in with your OAuth provider.
